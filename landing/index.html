Shared mailboxes

A team address without a shared password

Every delegate signs in with their own invited Google or Microsoft identity. Managers create functional addresses, control delivery state, and grant the least access each person needs.

Read state, folders, stars, drafts, and Sent history are shared operational state. cmail uses familiar Exchange-style terminology in an independent Cloudflare-native implementation; it is not a Microsoft Exchange server.
ReadOpen messages and manage read or unread state.
Send asIncludes reading and lets a delegate compose or reply from the shared address.
Full accessAdds shared folder moves, stars, archive, trash, and restore controls.

Cloudflare-native architecture

The web application and inbound Worker share D1 and R2 resources while keeping interactive and mail-routing responsibilities separate.

Inbound

Email Routing invokes the Worker. It validates the recipient, parses the message, and stores metadata and content.

Routing → Worker → D1 + R2

Interactive and outbound

Cloudflare Pages runs the SvelteKit app. Authenticated users read mail and submit external delivery to a configured provider.

Browser → Pages → D1 + R2 → provider

Bring your own domain and providers

Clone the repository, create D1 and R2 resources, register OAuth callbacks, store secrets in Cloudflare, and verify mail flow before routing real traffic.

cmail is pre-1.0 software. Complete the repository's deployment and security checklists, define backups, and test with controlled accounts before production use.
